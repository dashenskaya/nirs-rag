# Техническая архитектура Meme Helper

## Версия 2026-11-17: локальный бэкенд

Python 3.10+, стандартная библиотека: http.server, sqlite3, hashlib.
Внешние зависимости не нужны. Для проверки на одном компьютере HTTP-сервер раздаёт
интерфейс и API на одном адресе: http://127.0.0.1:8000.
Это локальный учебный сервер, не конфигурация для публичного развёртывания.

Путь запроса: браузер → HTTP API → SearchProvider → модуль RAG → ответ и источники → браузер.
Браузер не обращается к LLM напрямую. Изменения профиля и история сохраняются в SQLite.

## Данные

`var/memehelper.sqlite3`, отдельное соединение на запрос, транзакции, foreign_keys и WAL.

- users: login (PK), nickname, avatar, password_hash, role.
- sessions: SHA-256 случайного токена, login, expires.
- chats: id (PK), login владельца, title, updated_at, messages (JSON).
- memes: id, data (JSON-каталог и метаданные показанных мемов).
- events: id, query, status (success/empty/error), at, who, meme_ids, hidden.

Таблицы создаются автоматически через CREATE TABLE IF NOT EXISTS. Изменение схемы в будущем требует миграций.
Каталог MEME_CATALOG добавляется при старте, а метаданные выдачи обновляются при поиске.
Ранее показанные мемы сохраняются для исторической аналитики. Для эксперимента с полностью другим
корпусом используйте отдельный файл через `--db var/experiment.sqlite3`.
Текущая база служит локальному бэкенду. Реализацию хранения можно заменить с сохранением API.
Демо-данные localStorage не импортируются и не удаляются.

## API

Все данные — JSON UTF-8. Изменяющие запросы требуют заголовок `X-Requested-With: MemeHelper`.
Cookies передаются автоматически при запросах с того же адреса.

| Метод и путь | Вход | Результат / доступ |
|---|---|---|
| GET /api/health | — | status: ok, searchMode: demo или rag |
| GET /api/me | — | пользователь либо null |
| POST /api/auth/register | login, nickname, password | пользователь + cookie сессии |
| POST /api/auth/login | login, password | пользователь + cookie сессии |
| POST /api/auth/logout | {} | ok: true, сессия отзывается |
| PATCH /api/me | nickname, avatar | обновлённый пользователь; только роль user |
| GET /api/chats | — | список {id,title,updatedAt}; роль user |
| GET /api/chats/:id | — | чат с messages; только владелец |
| PUT /api/chats/:id | id, title, messages | сохранённый чат; только владелец |
| DELETE /api/chats/:id | — | ok: true; только владелец |
| POST /api/search | query | results, answer, sources, mode; доступен гостю |
| GET /api/admin/stats?period=day\|week | — | period,total,byDay,users,empty,errors; admin |
| GET /api/admin/memes | — | top: [{id,name,image,shows}], dead: [{id,name,image}]; admin |
| GET /api/admin/empty-queries | — | [{id,query,at}]; admin |
| DELETE /api/admin/empty-queries/:id | — | скрыть запись, сохранив статистику; admin |

Пользователь: {login,nickname,avatar,role}; пароль и хеш наружу не выдаются.
Чат: {id,title,updatedAt,messages}. updatedAt назначает сервер в миллисекундах Unix.
Структуру messages задаёт chat.js; успешный ответ хранит results, answer, sources, mode.
Сайт сохраняет завершённый диалог после поиска; гостевой чат хранится только в памяти страницы.
История сохраняется для просмотра; текущий вызов RAG получает один query, без истории диалога.
Продолжение чата пока означает добавление запросов в тот же чат, а не понимание местоименных ссылок моделью.

## Ошибки и ограничения

Ответ ошибки: {"error":"понятное сообщение"}.
400 — неверные поля; 401 — нет сессии; 403 — недостаточно прав/чужой источник;
404 — ресурс отсутствует (в том числе чужой чат); 409 — занят логин;
413 — размер запроса вне диапазона; 415 — неверный Content-Type;
502 — исключение или неверный ответ RAG; 500 — внутренняя ошибка сервера.

Запрос: максимум 2 МБ; query: 1–1000 символов; логин: [a-z0-9_.-], 3–20 символов;
пароль: 6–128 символов; никнейм: 1–30; фото: data URL JPEG/PNG/WebP до 300000 символов;
чат: до 500 сообщений, заголовок до 200 символов.

Пароли: PBKDF2-HMAC-SHA256, отдельная случайная соль, 260000 итераций.
Сессия: криптографически случайный токен, хранится в HttpOnly SameSite=Strict cookie на 7 дней;
в базе хранится только его SHA-256. Logout удаляет серверную сессию.
Cookie Secure для локального HTTP не используется; для публичного HTTPS нужно включить.
Все SQL-запросы используют параметры. Роль нельзя назначить из формы регистрации.
Администратор создаётся отдельной консольной командой с вводом пароля.
Проверка Host, Origin и обязательный нестандартный заголовок ограничивают запросы с чужих сайтов.

## Аналитика

Периоды рассчитываются по Москве (UTC+3): сегодня либо сегодня и шесть предыдущих календарных дней.
Активность — уникальные идентификаторы отправителей поиска за эти семь дней; гости определяются cookie,
а не физическими людьми. Очистка cookie или другой браузер создают нового гостя.
Доли empty/errors считаются от всех валидных обработанных поисковых запросов периода.
Ошибки проверки входных данных не являются событиями поиска.
Ошибка RAG учитывается как error и никогда не попадает в список empty.
Крестик ставит hidden=1, не удаляя событие и не меняя счётчики.
Показ — попадание мема в выдачу поиска, не скачивание и не просмотр старого чата.
