# Интерфейс подключения RAG

Обработчик поиска: `POST /api/search`. Ответ содержит `results`, `answer`, `sources` и `mode`.

## Внешний запрос

```json
{"query":"Что написать перед сном?"}
```

query — строка от 1 до 1000 символов. История чата пока не передаётся.

## Вызов Python-модуля

Переменная окружения RAG_PROVIDER задаёт `имя.модуля:имя_функции`.
Например, для app/rag_service.py с функцией search: `app.rag_service:search`.
При загрузке импортируется только этот явно указанный модуль; пользователь сайта не может выбрать модуль.

```python
def search(query: str) -> dict:
    # 1. retrieve(query): собственный BM25 по корпусу
    # 2. сборка контекста с ID документов
    # 3. вызов LLM, ответ только по контексту
    # 4. преобразование в формат ниже
    ...
```

Можно использовать async def. Внутри модуля задайте таймаут LLM и ограничьте время обработки:
браузер прекращает ожидание через 120 секунд; сервер не может принудительно остановить зависшую обычную функцию.
Провайдер должен поддерживать параллельные вызовы; индекс обычно загружается при импорте.
Ключи и настройки LLM читайте из переменных окружения, не возвращайте их в ответе.
Зависимости модуля RAG указываются в requirements.txt с инструкцией установки.

## Возвращаемый объект

Пример ответа:

```json
{
  "results": [
    {
      "meme": {
        "id": "volk-na-krayu",
        "name": "Ты точно не ложишься на краю?!",
        "image": "images/volk.jpg",
        "year": null,
        "origin": "Отсылка к колыбельной про серенького волчка.",
        "relevance": "Пожелание спокойной ночи"
      },
      "explanation": "Мем подходит для шуточного пожелания перед сном.",
      "suggestion": "Спокойной ночи! [изображение]"
    }
  ],
  "answer": "Можно отправить мем с волком: он связан с пожеланием перед сном. [D01]",
  "sources": [
    {"id": "D01", "text": "Точный найденный фрагмент документа корпуса."}
  ]
}
```

- results: от 0 до 5 объектов. Все показанные ключи meme обязательны; year может быть null.
- image: локальный путь images/... или /images/... либо HTTPS URL.
- explanation, suggestion, answer: строки.
- sources: найденные документы в порядке BM25 до финального отбора мемов моделью, без повторов ID.
  Каждый содержит непустые id и text; ID совпадают с корпусом бенчмарка.
  Используется для расчёта Recall@k и MRR.
- origin описывает происхождение мема; sources обозначает документы, использованные для ответа.
- mode добавляет сервер: demo либо rag.

Если информации нет:

```json
{"results":[],"answer":"В документах нет подходящей информации.","sources":[]}
```

Если найдены нерелевантные кандидаты, допустимо сохранить их в sources для оценки поиска,
но ответ должен быть отказом, а results — пустым.
При недоступности LLM или другой технической ошибке выбросьте исключение:
сервер вернёт 502 и запишет событие error. Нельзя подменять техническую ошибку отказом.

## Каталог и данные

MEME_CATALOG — путь к JSON-массиву полного каталога мемов с id,name,image (минимум).
Без него в режиме rag админка знает только ранее показанные мемы и не может перечислить все непоказанные.
Для каждого мема можно использовать отдельный текстовый документ или несколько фрагментов;
ID документов и ID мемов могут различаться — сопоставление выполняет модуль RAG.

## Требования к RAG

Поиск использует собственную реализацию BM25, формирует контекст и передаёт его LLM.
Требования к корпусу и оценке: [benchmark/README.md](../../benchmark/README.md).
