# SDD — Product

## 1. Название продукта

**Meme Helper**

---

## 2. Назначение продукта

Meme Helper — веб-сервис для интеллектуального поиска мемов по естественноу описанию.

Вместо поиска по точному названию мема или набору ключевых слов пользователь может описать ситуацию, в которой он хочет использовать мем, а система самостоятельно определит подходящий контекст и предложит релевантные варианты.

Поиск выполняется по базе мемов, содержащей:

* изображения мемов;
* названия;
* теги;
* описания;
* контекст и особенности использования;
* дополнительную информацию, необходимую для семантического поиска.

Для поиска применяется технология **RAG (Retrieval-Augmented Generation)**.

LLM-модель используется для интерпретации запроса и формирования понятного пользователю ответа.

---

## 3. Основная ценность продукта

Основная задача Meme Helper — сократить время поиска подходящего мема и сделать юмор более понятным для обывателя.

Пользователь не обязан:

* помнить название мема;
* знать происхождение изображения;
* искать мем вручную по десяткам сайтов;
* самостоятельно подбирать текст к найденной картинке.

---

## 4. Целевая аудитория

### 4.1. Основной пользователь

* Человек, который хочет найти новые для себя мемы
* Человек, который ищет, как по-смешному ответить на сообщение
* Человек, акоторый хочет разобраться в новых мемах

Пользователь не обязан обладать специальными техническими знаниями.

---

### 4.2. Аутентифицированный пользователь

Пользователь, который дополнительно хочет:

* сохранять контекст предыдущих диалогов;
* возвращаться к ранее начатым чатам;
* иметь персональный профиль.

---

# 5. Основные задачи пользователя

## 5.1. Найти мем

Пользователь описывает ситуацию естественным языком.

Пример:

> «Что мне ответить на такое сообщение: "Ты лузер!"»

Система должна подобрать наиболее подходящие мемы.

---

## 5.2. Найти мем по контексту

Пользователь может описать не конкретную фразу, а общую ситуацию:

> «Нужен мем, чтобы отправить человеку, который опять пришёл поздно».

Система должна учитывать смысл запроса.

---

## 5.3. Найти мем по характеристикам

Пользователь может задавать ограничения:

> «Нужен мем с котом, который можно отправить маме, желательно с надписью».

Система должна использовать описанные ограничения при подборе.

---

## 5.4. Получить объяснение

Результат поиска должен быть не только набором изображений.

Для каждого рекомендуемого мема система должна предоставлять понятное объяснение, например:

* что это за мем;
* откуда он появился;
* в каком контексте используется;
* какое сообщение можно отправить вместе с ним.

---

## 5.5. Получить несколько вариантов

Один запрос должен возвращать **5 или менее наиболее релевантных вариантов**, чтобы пользователь мог выбрать наиболее подходящий.

---

## 5.6. Сохранять историю

После авторизации пользователь получает доступ к истории своих чатов.

История позволяет:

* открыть предыдущий диалог;
* посмотреть предыдущие запросы;
* продолжить существующий чат.

---

## 5.7. Управлять профилем

Аутентифицированный пользователь может изменить:
* никнейм;
* фотографию профиля.
Также пользователь может выйти из аккаунта.

---

# 6. Основные функциональные возможности продукта

### Поиск

Система должна:

1. принимать текстовый запрос;
2. анализировать смысл запроса;
3. выполнять семантический поиск по базе мемов;
4. использовать RAG для получения релевантных данных;
5. передавать найденный контекст LLM;
6. формировать итоговый ответ;

### Работа с мемами

Каждый мем должен иметь набор метаданных, достаточных для его поиска и описания.

Минимально предполагаются:

* изображение;
* название/идентификатор;
* описание;
* теги;
* контекст использования.

### Работа с пользователями

Система должна поддерживать:

* регистрацию;
* аутентификацию;
* выход;
* редактирование профиля;
* хранение истории чатов.

---

# 7. Основные сущности продукта

## Пользователь

Содержит данные учетной записи и профиля.

Основные данные:

* идентификатор;
* логин/учетные данные;
* фотография профиля;

---

## Чат

Представляет отдельный пользовательский диалог с системой.

Чат содержит:

* идентификатор;
* пользователя-владельца;
* дату создания;
* сообщения;

---

## Сообщение

Сообщение является отдельным запросом пользователя или ответом системы.

Для сообщения могут храниться:

* идентефикатор;
* текст;
* время отправки;

---

## Мем

Мем представляет единицу контента, по которой осуществляется поиск.

Мем может содержать:

* идентефикатор
* изображение;
* описание;
* набор тегов;
* контекст;
* дополнительную информацию для LLM/RAG.

---

## Тег

Используется для тематической классификации мемов.

Теги могут участвовать как в поиске, так и в административной статистике.

# 9. Нефункциональные требования

## 9.1. Интерфейс

Сайт должен быть понятен пользователю без дополнительного обучения.

Основной сценарий должен строиться вокруг одного действия:

**описать ситуацию → получить подходящие мемы.**

---

## 9.2. Ответ системы

Система должна показывать пользователю понятный статус обработки запроса.

Минимально должны поддерживаться состояния:

* запрос отправляется;
* ответ формируется;
* результаты получены;
* результатов нет;
* произошла ошибка.

---

## 9.3. Персональные данные

Доступ к истории чатов должен предоставляться только владельцу соответствующего аккаунта.

---

## 9.4. Масштабирование

Архитектура продукта должна позволять в будущем:

* увеличивать количество мемов;
* расширять набор тегов;
* изменять LLM;
* изменять механизм поиска;
* добавлять новые типы пользовательских запросов.

---

# 10. Результат использования продукта

После использования Meme Helper пользователь должен получить не просто изображение, а **готовое решение для коммуникации**:

**ситуация → подходящий мем → объяснение → готовый вариант сообщения.**

Это является основным функциональным преимуществом продукта.
