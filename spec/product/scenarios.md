# SDD — Scenarios

## 1. Общая информация

Документ описывает основные пользовательские сценарии **Meme Helper** — сервиса интеллектуального поиска мемов с использованием RAG и LLM.

Основной пользовательский сценарий системы заключается в том, что пользователь формулирует естественным языком ситуацию, для которой ему нужен мем. Система анализирует запрос, осуществляет поиск по базе мемов с использованием RAG и возвращает пять наиболее подходящих вариантов с пояснением контекста каждого мема и примером сообщения, которое пользователь может отправить вместе с ним.

Система поддерживает два типа пользователей:

* неаутентифицированный пользователь;
* аутентифицированный пользователь.

---

## 2. UC-01 — Поиск мема по конкретной ситуации

### Назначение

Позволить пользователю искать мем не по названию, а по описанию ситуации.

### Пример запроса

> «Что мне ответить на такое сообщение: "Ты лузер!"?»

### Основной сценарий

1. Пользователь переходит на главную страницу сайта и видит интерфейс чата и поле для ввода запроса.
2. Пользователь вводит запрос в чат и отправляет его.
3. Система отображает состояние загрузки и начинает обработку запроса.
4. По запросу выполняется поиск по базе мемов с использованием механизма RAG.
5. Система выбирает пять наиболее релевантных мемов.
6. LLM-модель формирует пояснение по каждому найденному мему.
7. Для каждого варианта система может указать:
   * картинку мема;
   * название мема;
   * контекст и примерное время возникновения;
   * значение или смысл мема;
   * пример сообщения, которое можно отправить вместе с мемом.
8.  Система выводит результаты в интерфейсе чата.
9.  В зависимости от того, аутентифицирован ли пользователь, данные о чате либо сохраняются в сайдбаре с чатами, либо нет

### Результат

Пользователь получает пять вариантов мемов, подходящих под описанную им ситуацию.

## 3. UC-02 — Поиск мема по нескольким характеристикам

### Назначение

Позволить пользователю указывать одновременно ситуацию, желаемую тематику, объект изображения и наличие текста.

### Пример запроса

> «Хочу найти мем, который можно отправить маме, желательно с котиком и какой-нибудь надписью».

### Основной сценарий

1. Пользователь переходит на главную страницу сайта и видит интерфейс для ввода сообщений.
2. Пользователь формирует текстовый запрос.
3. Система извлекает из запроса смысловые признаки.
4. Выполняется семантический поиск по базе мемов.
5. Система учитывает:
   * контекст использования;
   * тематику;
   * теги;
   * описание изображения;
   * дополнительные смысловые ограничения.
6. Выбираются пять наиболее подходящих мемов.
7. LLM объясняет соответствие каждого варианта запросу.
8. В зависимости от того, аутентифицирован ли пользователь, данные о чате либо сохраняются в сайдбаре с чатами, либо нет

## 4. UC-03 — Регистрация пользователя

### Назначение

Создать учетную запись пользователя.

### Предусловия

Пользователь находится на основном экране и не авторизован.

### Основной сценарий

1. Пользователь нажимает на кнопку регистрации.
2. Система открывает модальное окно входа поверх основного интерфейса.
3. Пользователь вводит необходимые данные.
4. Пользователь отправляет форму.
5. Система проверяет корректность введенных данных.
6. Система создает учетную запись.
7. Пользователь автоматически авторизуется либо получает сообщение об успешной регистрации.
8. Основной интерфейс обновляется.
9. Вместо кнопки входа/регистрации отображается профиль пользователя и его никнейм.

### Ошибки

При некорректных или уже занятых данных система должна показать сообщение об ошибке и предложить исправить форму.

---

## 5. UC-04 — Аутентификация пользователя

### Назначение

Войти в учетную запись пользователя.

### Предусловия

Пользователь находится на основном экране и не авторизован.


### Основной сценарий

1. Пользователь нажимает на иконку входа.
2. Открывается модальное окно авторизации.
3. Вводит логин и пароль.
4. Система проверяет учетные данные.
5. При успешной аутентификации система создает пользовательскую сессию.
6. Основной интерфейс обновляется.
7. В левом сайдбаре становится доступна история чатов пользователя.
8. Иконка входа заменяется профилем и никнеймом пользователя.

### Ошибка аутентификации

При неверных учетных данных система отображает уведомление об ошибке и оставляет пользователя на форме входа.

---

## 6. UC-05 — Просмотр истории чатов

### Назначение

Открыть предыдущие диалоги


### Предусловия

Пользователь авторизован.

### Основной сценарий

1. Пользователь открывает основной экран.
2. В левой части интерфейса отображается сайдбар.
3. Система загружает историю чатов пользователя.
4. В сайдбаре отображаются предыдущие диалоги.
5. Пользователь выбирает один из них.
6. Система открывает соответствующий чат.

### Результат

Пользователь может продолжить ранее начатый диалог.

---

## 7. UC-06 — Настройка профиля

### Назначение

Настроить профиль под свой вкус

### Предусловия

Пользователь авторизован.

### Основной сценарий

1. Пользователь нажимает на область профиля в правом верхнем углу.
2. Система открывает модальное окно профиля поверх основного интерфейса.
3. Пользователь видит текущие данные профиля.
4. Пользователь может изменить:
   * никнейм;
   * фотографию профиля.
5. Пользователь сохраняет изменения.
6. Система сохраняет изменения.
7. Интерфейс обновляется без необходимости перезагрузки страницы.

---

## 8. UC-07 — Выход из аккаунта

### Назначение

Сменить аккаунт или не сохранять запрос в историю

### Предусловия

Пользователь авторизован.

### Основной сценарий

1. Пользователь открывает окно профиля.
2. Нажимает кнопку «Выйти».
3. Система завершает пользовательскую сессию.
4. История чатов перестает быть доступной.
5. Интерфейс возвращается в состояние неаутентифицированного пользователя.

---

## 9. UC-8 — Поиск без результатов

### Назначение

Не обманывать пользователя

### Предусловия

Пользователь отправил корректно сформированный запрос.

### Основной сценарий

1. Система анализирует запрос.
2. Поиск не находит релевантных мемов.
3. Система не формирует фиктивные результаты.
4. Пользователю отображается сообщение о том, что подходящие мемы не найдены.
5. Пользователю предлагается изменить или уточнить запрос.
