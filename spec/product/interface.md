# SDD — Interface

## 1. Общая структура интерфейса

Система содержит следующие пользовательские экраны:

1. основной экран поиска мемов;
2. окно регистрации/аутентификации;
3. окно настроек профиля.

Регистрация, аутентификация и настройки профиля открываются **поверх основного экрана**, не заменяя его.

---

# 2. Страница 1 — Основной экран Meme Helper

## Назначение

Основной экран является центральной частью продукта. Здесь пользователь выполняет поиск мемов и взаимодействует с системой в формате чата.

---

## 2.1. Структура страницы

Основной экран должен состоять из трех основных областей:

### Левая область — Sidebar

Сайдбар используется для отображения истории чатов.

Для неаутентифицированного пользователя отображается ограниченный вариант интерфейса без истории персональных чатов.

Для аутентифицированного пользователя отображается список предыдущих чатов;

---

### Центральная область — Chat

Центральная часть содержит:

* сообщения пользователя;
* изображения найденных мемов;
* пояснения LLM;
* поле ввода нового сообщения.

---

### Правая верхняя область — Profile

В правом верхнем углу располагается элемент управления учетной записью.

Для неавторизованного пользователя:

* Кнопка вход, переход к регистрации осуществляется через неё.

Для авторизованного пользователя:

* аватар;
* никнейм.

При нажатии открывается окно настроек профиля.

---

# 3. Состояние пустого чата

При первом открытии сайта пользователь должен увидеть пустое состояние.

Интерфейс должен кратко объяснять предназначение сервиса.

Например:

> «Опишите ситуацию, и Meme Helper подберёт 5 подходящих мемов.»

Ниже располагается поле ввода запроса.

Допустимые типы запросов:

* описание ситуации;
* цитата из сообщения;
* описание желаемого мема;

---

# 4. Поле ввода

Поле ввода является основным элементом управления.

Пользователь должен иметь возможность написать запрос в свободной форме.

Пример:

> «Что ответить человеку, который назвал меня лузером?»

Под полем/рядом с полем должна располагаться кнопка отправки.

При отправке:

1. пользовательское сообщение появляется в чате;
2. поле ввода очищается;
3. система показывает состояние обработки;
4. после получения результата отображается ответ.

---

# 5. Состояние загрузки

Во время поиска интерфейс должен показывать, что запрос обрабатывается.

Например:

> «Ищу подходящие мемы…»

На время обработки интерфейс должен предотвращать повторную отправку одного и того же запроса, если это необходимо для корректной работы клиента.

---

# 6. Ответ системы

Ответ системы должен содержать пять или меньше рекомендуемых мемов.

Каждый результат должен быть визуально отделён от остальных.

Рекомендуемая структура результата:

### Мем №1

* изображение;
* название;
* краткое описание и дополнительная информация;
* объяснение смысла;
* рекомендуемый текст сообщения.

Например:

> **Упячка**
> Мем появился в 2007 году и связан с бессмысленными наборами символов. В данном случае он подходит, потому что позволяет ответить абсурдно и иронично.
>
> **Можно написать:**
> «Да ты древнее этого мема: [изображение]»

Аналогичная структура используется для остальных четырёх результатов.

---

# 7. История чатов в Sidebar

## Для авторизованного пользователя

Система отображает список предыдущих диалогов.

Каждый элемент списка должен позволять перейти к соответствующему чату.

При выборе чата:

1. текущий диалог заменяется выбранным;
2. сообщения загружаются из истории;
3. пользователь может продолжить разговор.

---

## Для неавторизованного пользователя

История персональных чатов не отображается.

При необходимости в сайдбаре может быть показано предложение войти в аккаунт для сохранения истории.

---

# 8. Страница/окно 2 — Регистрация и аутентификация

Регистрация и вход должны открываться модальным окном поверх главной страницы.

Основной контент страницы при этом остается на фоне.

Первой открывается окно вхожа, сверху можно переключиться на колкно аутентификации

---

## 8.1. Авторизация

Форма входа должна содержать необходимые поля для аутентификации.

Минимально:

* логин;
* пароль;
* кнопка входа.

Также должна быть возможность перейти к регистрации.

При неправильных данных пользователь получает понятное сообщение об ошибке.

---

## 8.2. Регистрация

Форма регистрации содержит необходимые поля для создания аккаунта.

Минимально должен присутствовать набор данных, необходимый backend для создания пользователя.

После успешной регистрации пользователь получает доступ к персональному профилю.

---

## 8.3. Закрытие окна

Модальное окно должно иметь возможность закрытия.

После закрытия пользователь возвращается к текущему состоянию основного чата без потери введённых ранее данных, если это не нарушает логику приложения.

---

# 9. Состояние авторизованного пользователя

После успешного входа интерфейс изменяется.

Вместо кнопок:

> «Войти / Зарегистрироваться»

отображается:

> **Аватар + Никнейм**

Также становится доступен:

* персональный Sidebar;
* список прошлых чатов;
* профиль.

---

# 10. Страница/окно 3 — Настройки профиля

Окно профиля открывается поверх основного чата при нажатии на аватар или никнейм.

---

## 10.1. Данные профиля

Окно должно отображать и позволять изменять:

* никнейм;
* фотографию профиля.

---

## 10.2. Выход

В окне профиля должна присутствовать кнопка:

> **Выйти из аккаунта**

После выхода:

* пользователь теряет состояние авторизации;
* история персональных чатов становится недоступной;
* UI возвращается к состоянию гостя.

---

# 11. Общие состояния интерфейса

Для основных компонентов необходимо предусмотреть следующие состояния:

### Normal

Обычное состояние без выполняющейся операции.

### Loading

Система обрабатывает запрос или выполняет загрузку данных.

### Success

Операция завершена успешно.

### Empty

Нет данных для отображения.

Пример:

> «Подходящие мемы не найдены».

### Error

Произошла ошибка.

Например:

> «Не удалось получить рекомендации. Попробуйте ещё раз.»

### Unauthorized

Пользователь пытается получить доступ к функциональности, требующей авторизации.

---

# 12. Административная страница `/admin`

## Назначение

Административная страница предназначена для просмотра аналитики Meme Helper и анализа запросов, для которых система не смогла подобрать подходящие мемы.

## 12.1. Общая структура страницы

После успешной авторизации экран делится на две основные части:

- левая половина — статистическая информация и аналитические показатели;
- правая половина — список запросов, по которым не удалось найти подходящие мемы.

Обе части отображаются одновременно.

---

## 12.2. Левая часть — Аналитика

Аналитические показатели располагаются вертикально, один под другим.

### Количество запросов

Отображается количество запросов за выбранный период.

Пользователь интерфейса может выбрать один из периодов:

- день;
- неделя.

Для недельного периода дополнительно отображается график количества запросов по дням(распологается внизу левой части страницы).

### Активность пользователей

Отображается количество активных пользователей за последнюю неделю с разделением на две категории:

- гости;
- зарегистрированные пользователи.

Количество гостей и зарегистрированных пользователей должно рассчитываться отдельно и отображаться в двух подписанных полях рядом друг с другом.

### Доля ответов «Не найдено»

Отображается доля запросов, для которых поиск не вернул подходящих мемов.

В эту категорию входят успешно обработанные запросы без результатов, но не технические ошибки.

### Доля технических ошибок

Отображается доля запросов, обработка которых завершилась технической ошибкой.

---

## 12.3. Правая часть — Запросы без результатов

Правая половина страницы содержит три подписанных блокас разными списками:

### Наиболее часто показываемые мемы

Отображается список мемов, которые чаще всего попадали в результаты поиска.

Для каждого мема показывается название и количество показов.

Если список большой, должна поддерживаться прокрутка.

### «Мёртвые» мемы

Отображается список мемов, которые ни разу не попадали в результаты поиска за весь период наблюдения.

Если список большой, должна поддерживаться прокрутка.

### запросы, по которым система не смогла подобрать подходящие мемы.

Для каждой записи отображаются:

- текст запроса;
- дата и время отправки;

Список должен позволять просматривать все сохраненные записи. Для этого используектся прокрутка. С правого края каждой записи стоит крестик, который позволяет удалить запись из этой таблицы

Технические ошибки не должны отображаться в списке запросов без результатов, поскольку они относятся к другой категории статистики.

Если подходящих записей нет, система показывает сообщение:

«Запросов без результатов нет».

---

## 12.4. Состояния административной страницы

При загрузке аналитики система отображает состояние загрузки.

Если данные успешно загружены, система показывает статистические показатели и список запросов.

Если данных для отдельного показателя нет, система отображает соответствующее пустое состояние.

При ошибке загрузки система сообщает, что получить данные не удалось, и предоставляет возможность повторить загрузку.

Если администратор не авторизован или не имеет соответствующих прав, доступ к аналитике и списку запросов не предоставляется. Показывается пустая плашка "Доступ к данной странице вам не выдан. Админ бы вас могнул."
