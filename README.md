# Meme Helper

Веб-приложение для подбора мемов по описанию ситуации.

## Команда

- Бабере Виктория — интерфейс.
- Николаева Дарья — бэкенд.
- Шерстеникин Никита — база мемов и интеграция RAG.

## Возможности

- Сервер на Python 3.10+; для RAG нужны `pymorphy3` и `boto3`.
- Регистрация, вход, выход, профиль с фотографией.
- История чатов в SQLite, доступная только владельцу.
- Админка с настоящей статистикой запросов, показами мемов и запросами без результатов.
- Сайт обращается к серверу, данные больше не хранятся в localStorage.
- Подключение модуля RAG через одну функцию, отображение ответа и источников.

## Запуск в Windows

1. Откройте PowerShell в папке проекта.
2. Один раз установите зависимости: `python -m pip install -r requirements.txt`.
3. Скопируйте `.env.example` в `.env` и заполните параметры LLM и MinIO.
4. Если нужны изображения мемов, запустите MinIO по инструкции в разделе [«Локальный MinIO и загрузка изображений»](#локальный-minio-и-загрузка-изображений). При повторном запуске достаточно выполнить `docker start memehelper-minio`.
5. Выполните команду `.\start.cmd` (не закрывайте это окно).
6. Дождитесь строки `Meme Helper: http://127.0.0.1:8000`.
7. Откройте в браузере **http://127.0.0.1:8000**.
8. Для остановки нажмите **Ctrl+C** в окне сервера.

Теперь сайт нужно открывать по этому адресу, а не двойным нажатием на index.html.
Повторный запуск сохраняет аккаунты, чаты и статистику.
Используйте один адрес: `127.0.0.1` и `localhost` имеют разные браузерные cookies.

Если порт занят, откройте PowerShell в папке проекта и выполните:

```powershell
.\start.cmd --port 8001
```

Затем откройте `http://127.0.0.1:8001`.

Скрипт использует установленный Python, а на этом компьютере также умеет использовать Python из Codex.
На другом компьютере установите Python 3.10+ с python.org, включив **Add Python to PATH**.
При обновлении Codex резервный путь может измениться; обычный установленный Python продолжит работать.

Обычный запуск, если Python установлен:

```powershell
cd C:\nirs\nirs-rag
python run.py
```

## Ручная проверка

1. Отправьте `Друг прислал смешную шутку` — должна появиться карточка с окном.
2. Отправьте `Спокойной ночи` — должна появиться карточка с волком.
3. Разверните «Источники» под ответом.
4. Отправьте `Грустный пельмень` — появится сообщение, что результатов нет.
5. Нажмите «Войти» → «Регистрация», придумайте логин и пароль. Логин: 3–20 символов латиницей, цифры, точка, _ или -; пароль: 6–128 символов.
6. Отправьте ещё запрос. Чат появится слева. Обновите страницу и откройте его снова.
7. Откройте профиль, измените никнейм и фото. Обновите страницу: изменения сохранятся.
8. Выйдите: история станет недоступной. Войдите снова: история вернётся.
9. Создайте другой аккаунт: он не должен видеть чаты первого.
10. Остановите и заново запустите сервер: аккаунты и чаты должны сохраниться.

## Как проверить админку

Универсального пароля администратора нет. Один раз создайте отдельного администратора:

```powershell
cd C:\nirs\nirs-rag
.\start.cmd --create-admin admin
```

Дважды введите придуманный пароль (символы при вводе не видны). Если логин занят, выберите другой.
Затем запустите `start.cmd`, войдите под этим аккаунтом и откройте `http://127.0.0.1:8000/admin`.
Можно также открыть аналитику из окна профиля.

- Статистика учитывает только реальные запросы, отправленные этому серверу.
- До первых запросов показатели пустые — это нормальное состояние.
- Крестик скрывает запрос без результатов из списка, но не меняет статистику.
- Обычному пользователю и гостю аналитика недоступна.
- По таблице ролей в spec администратор имеет аналитику и выход; персональная история и редактирование профиля доступны обычному пользователю.

## Автоматические проверки

Дважды нажмите **check.cmd**. В конце должно быть `OK`.
Проверки используют временные базы и не меняют ваши аккаунты и чаты.

Или выполните:

```powershell
python -m unittest discover -s tests -v
```

Проверяются регистрация, сессии, пароли, изоляция чатов, профиль, права админа, поиск,
учёт ошибок, скрытие запросов, защита служебных файлов, подключение RAG, BM25 и формулы метрик.

## Настройка RAG: pymorphy3, BM25, LLM и MinIO

По умолчанию `run.py` подключает `app.backend.meme_rag:search`. Для его работы установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Скопируйте шаблон и заполните файл `.env` в корне проекта (значения возьмите у своего провайдера LLM и администратора MinIO):

```powershell
Copy-Item .env.example .env
notepad .env
```

`run.py` сам читает `.env`; переменные, уже заданные в Windows, имеют приоритет. Секретный `.env` исключён из Git.

```dotenv
LLM_API_BASE=https://api.openai.com/v1
LLM_API_KEY=ВАШ_СЕКРЕТНЫЙ_КЛЮЧ
LLM_MODEL=gpt-6.2-sol

MINIO_ENDPOINT=http://127.0.0.1:9000
MINIO_ACCESS_KEY=ВАШ_MINIO_ACCESS_KEY
MINIO_SECRET_KEY=ВАШ_MINIO_SECRET_KEY
MINIO_BUCKET=meme-images
MINIO_REGION=us-east-1
MINIO_PRESIGNED_EXPIRES=900
```

`LLM_API_BASE` должен указывать на OpenAI-совместимый API, который поддерживает `POST /chat/completions`. Для локального совместимого сервера API-ключ можно оставить пустым. Ключи не отправляются браузеру и не должны попадать в Git.

Для OpenAI в этом примере используется модель `gpt-6.2-sol`. Если выбран другой API-провайдер, укажите его точный идентификатор модели и адрес API. `LLM_API_KEY` — секретный ключ API, а не пароль от ChatGPT. Получить ключ можно в [OpenAI Platform → API keys](https://platform.openai.com/api-keys): откройте нужный проект, нажмите **Create new secret key**, скопируйте ключ и сохраните его сразу — полностью посмотреть его повторно нельзя. Использование API оплачивается отдельно от подписки ChatGPT; перед включением платного использования проверьте настройки расходов и лимитов в API Platform. Если пользователь младше 18 лет, условия OpenAI требуют разрешения родителя или законного представителя; вопросы аккаунта и оплаты следует решать с ним. Никому не отправляйте секретный ключ и не добавляйте его в Git.
Важно для `gpt-6.2-sol`: в текущем `app/backend/meme_rag.py` в `payload` передаётся параметр `'temperature': 0.2`. Для GPT-6.2 в Chat Completions этот параметр нужно убрать. Перед первым запросом удалите строку `'temperature': 0.2,` из словаря `payload` в функции `_call_llm`. Остальные параметры запроса остаются без изменений. Это ограничение самой модели и API, а не настройка `.env`.

### Локальный MinIO и загрузка изображений

В проекте нет отдельной формы для загрузки изображений мемов. Файл сначала загружается в MinIO, а затем в базу добавляется запись с `image_key` — именем объекта внутри bucket. Ссылка на картинку формируется сервером при её открытии. Инструкция ниже описывает локальный запуск MinIO в Windows через Docker Desktop.

#### 1. Запустите MinIO

1. Установите Docker Desktop и запустите его.
2. Откройте PowerShell.
3. Создайте папку, в которой MinIO будет хранить файлы:

```powershell
New-Item -ItemType Directory -Force C:\minio\data | Out-Null
```

4. Запустите контейнер MinIO. В команде замените пароль на свой длинный случайный пароль и запомните его:

```powershell
docker run -d --name memehelper-minio `
  -p 9000:9000 `
  -p 9001:9001 `
  -v C:\minio\data:/data `
  -e "MINIO_ROOT_USER=memehelper_admin" `
  -e "MINIO_ROOT_PASSWORD=REPLACE_WITH_YOUR_LONG_PASSWORD" `
  quay.io/minio/minio server /data --console-address ":9001"
```

MinIO предоставляет S3 API на `http://127.0.0.1:9000`, а веб-панель — на `http://127.0.0.1:9001`. Данные сохраняются в `C:\minio\data`, поэтому не пропадают при остановке контейнера.

При последующих запусках контейнера повторять `docker run` не нужно — выполните:

```powershell
docker start memehelper-minio
```

Остановить MinIO можно командой `docker stop memehelper-minio`. Посмотреть, работает ли контейнер, — `docker ps`.

#### 2. Создайте bucket и настройте `.env`

1. Откройте `http://127.0.0.1:9001`.
2. Войдите с логином `memehelper_admin` и паролем, который указали в `MINIO_ROOT_PASSWORD` при запуске контейнера.
3. Откройте раздел **Buckets** и создайте bucket с именем `meme-images`.
4. Оставьте bucket приватным: не включайте публичный или анонимный доступ.
5. В `.env` укажите те же локальные MinIO-учётные данные, что были переданы контейнеру:

```dotenv
MINIO_ENDPOINT=http://127.0.0.1:9000
MINIO_ACCESS_KEY=memehelper_admin
MINIO_SECRET_KEY=ТОТ_ЖЕ_ПАРОЛЬ_ЧТО_MINIO_ROOT_PASSWORD
MINIO_BUCKET=meme-images
MINIO_REGION=us-east-1
MINIO_PRESIGNED_EXPIRES=900
```

`MINIO_ACCESS_KEY` должен совпадать с `MINIO_ROOT_USER`, а `MINIO_SECRET_KEY` — с `MINIO_ROOT_PASSWORD`. Такой вариант предназначен для локального учебного запуска. Для размещения приложения на сервере следует создать отдельного MinIO-пользователя с ограниченными правами, а не использовать root-учётные данные.

#### 3. Загрузите файл изображения в MinIO

1. В MinIO Console откройте bucket `meme-images`.
2. При необходимости создайте внутри него папку `memes`.
3. Откройте папку `memes` и нажмите **Upload** / **Upload file**.
4. Выберите изображение на компьютере, например `meme-001.jpg`.
5. После загрузки полный ключ объекта будет `memes/meme-001.jpg`.

Именно этот ключ, а не URL из браузера и не адрес MinIO, нужно передать в поле `image_key` при добавлении мема.

#### 4. Создайте запись о меме

После загрузки файла добавьте его метаданные по инструкции в разделе [«Добавление мема»](#добавление-мема). В поле `image_key` укажите получившийся ключ, например `memes/meme-001.jpg`. Для вызова API нужно войти на сайт под администратором. Отдельной формы загрузки файлов в текущей админ-панели нет.

#### 5. Перенесённые демонстрационные изображения

При первом создании каталога проект переносит две демонстрационные записи из `app/backend/demo_memes.json`. Для показа этих записей загрузите в bucket `meme-images` исходные файлы из `app/MemeHelper/images` с сохранением ключей:

- `images/okno.jpg`
- `images/volk.jpg`

То есть в MinIO создайте папку `images` и загрузите туда `okno.jpg` и `volk.jpg`. Если вы используете только собственные мемы, достаточно загружать их в свою папку, например `memes/`.

### База мемов и поисковый индекс

В той же SQLite-базе, что хранит пользователей и чаты (`var/memehelper.sqlite3`), автоматически создаются таблицы:

- `meme_catalog`: `id`, `name`, `description`, `history`, `image_key`, даты создания и обновления;
- `meme_terms`: нормализованные термины и их частоты отдельно для `name`, `description`, `history`;
- `meme_index_meta`: версия индекса для обновления кэша после добавления мема.

При добавлении или обновлении мем проходит токенизацию, очистку пунктуации и нормализацию `pymorphy3`; термины записываются в `meme_terms`. При поиске строится/обновляется индекс BM25. Веса полей: `name = 2.5`, `description = 2.0`, `history = 0.4`, поэтому история имеет существенно меньший вклад.

Два прежних демо-мема однократно переносятся при первом создании каталога: `meaning`, `relevance` и `fit` объединяются в `description`, `origin` становится `history`, а путь изображения — ключом MinIO. Порядок загрузки их файлов `okno.jpg` и `volk.jpg` описан выше в подразделе «Перенесённые демонстрационные изображения».

### Добавление мема

Добавлять записи может только администратор. Используйте `POST /api/admin/memes` с JSON:

```json
{
  "id": "meme-id",
  "name": "Название мема",
  "description": "Что изображено и что означает мем",
  "history": "Известная история происхождения; если данных нет — пустая строка",
  "image_key": "memes/meme-id.jpg"
}
```

`image_key` — именно ключ объекта внутри приватного bucket, не URL и не публичная ссылка. Сам файл должен быть предварительно загружен в MinIO. Добавление сразу перестраивает токеновый индекс для этой записи. Повторный `id` обновляет запись и её поисковые термины. Например, после входа администратором можно выполнить запрос из консоли браузера:

```javascript
fetch('/api/admin/memes', {
  method: 'POST',
  credentials: 'same-origin',
  headers: {
    'Content-Type': 'application/json',
    'X-Requested-With': 'MemeHelper'
  },
  body: JSON.stringify({
    id: 'meme-id',
    name: 'Название мема',
    description: 'Описание и значение мема',
    history: 'Известная история происхождения или пустая строка',
    image_key: 'memes/meme-id.jpg'
  })
}).then(response => response.json()).then(console.log);
```

### Поиск и ответ

`POST /api/search` принимает только `{"query":"текущее сообщение"}` и возвращает итоговый JSON. `POST /api/search/stream` принимает тот же объект и возвращает Server-Sent Events (`status`, `answer`, `result`, `done` или `error`); именно этот адрес использует чат. История чата и предыдущие сообщения в функцию поиска не передаются. BM25 ранжирует записи по полям `name`, `description`, `history` и `tags`; при явном совпадении с тегом применяется обязательная фильтрация по нему. LLM получает только текущий запрос и записи-кандидаты. Фактические название, описание и история в ответе берутся из БД, а LLM формирует только интерпретацию соответствия и пример сообщения. Если истории нет, backend явно указывает, что сведений об истории в БД нет.

Для картинок JSON содержит внутренний URL вида `/api/memes/<id>/image`. При обращении к нему сервер создаёт краткоживущую подписанную MinIO-ссылку и перенаправляет браузер. `image_key` и постоянная публичная ссылка не хранятся в чате и не передаются фронтенду.

При необходимости можно указать другой модуль через `RAG_PROVIDER=module:function`. Для нового RAG-провайдера должны быть доступны функции `search(query)`, `list_catalog()`, `add_meme(...)` и `get_image_url_for_meme_id(id)`, если нужны каталог, добавление и изображения.

## Требования к бенчмарку

Презентация «Занятие 3. RAG и BM25», слайды 37–42:

- самостоятельно реализованный BM25 + LLM, отвечающая по найденным документам;
- отказ, если в документах нет нужной информации;
- 30 документов, 10 обычных вопросов, по минимум 3 релевантных документа на вопрос;
- 5 вопросов-ловушек;
- сохранённая выдача и ответы; Recall@k, MRR, Accuracy, Correct Rejection Rate;
- краткий разбор ошибок и инструкция воспроизведения.

Требования к самостоятельной реализации индекса указаны в методичке, раздел 2, с. 8.
Инструкция по бенчмарку: [benchmark/README.md](benchmark/README.md).

## Файлы проекта

- `run.py`, `start.cmd` — запуск; `check.cmd` — тесты.
- `scripts/python.ps1` — выбор Python для запуска в Windows.
- `app/backend/server.py` — HTTP API, SQLite, пользователи, чаты, аналитика.
- `app/backend/rag.py` — подключение и проверка ответа RAG-провайдера.
- `app/backend/meme_rag.py` — база мемов, pymorphy3, индекс BM25, LLM и MinIO.
- `app/backend/demo_memes.json` — две исходные демонстрационные записи.
- `app/MemeHelper/` — веб-интерфейс.
- `tests/` — автоматические проверки.
- `benchmark/` — запуск учебного бенчмарка после подключения RAG.
- `spec/` — продуктовые требования и технические договорённости.
- `var/memehelper.sqlite3` — локальные данные, автоматически создаются при запуске.

Файл базы, служебные файлы SQLite, .env и кэш Python исключены через .gitignore.
Сервер раздаёт только файлы интерфейса; база и исходники бэкенда через сайт недоступны.
Сервер предназначен для локального учебного запуска и слушает только `127.0.0.1`.
