# Бенчмарк контрольной точки

## Набор dataset.json

Подготовьте benchmark/dataset.json с объектом:

```json
{
  "documents": [
    {"id":"D01","text":"Текст документа"}
  ],
  "questions": [
    {
      "id":"Q01",
      "text":"Вопрос, для которого нужны минимум три документа",
      "trap":false,
      "relevant_ids":["D01","D02","D03"],
      "expected_answer":"Полный эталонный ответ"
    },
    {
      "id":"T01",
      "text":"Вопрос, ответа на который нет в корпусе",
      "trap":true,
      "relevant_ids":[],
      "expected_answer":"В документах нет такой информации."
    }
  ]
}
```

Это только пример схемы: нужен полный набор из 30 документов, 10 обычных вопросов и 5 ловушек.
Запуск проверяет объём и ссылки на релевантные ID. Размечайте вопросы и эталоны до прогона.
Индекс RAG должен быть построен по этим же 30 документам.

## Прогон

В PowerShell из корня проекта, после подключения настоящего RAG:

```powershell
$env:RAG_PROVIDER = 'app.rag_service:search'
$env:MEME_CATALOG = 'app/rag_catalog.json'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/python.ps1 -m benchmark.run benchmark/dataset.json --k 3
```

При установленном Python можно заменить начало команды на `python -m benchmark.run ...`.
Выберите k заранее вместе с преподавателем. В реализации MRR вычисляется на той же глубине k
(то есть MRR@k), что явно сохраняется в отчёте. Если согласована другая глубина, измените её до сравнения версий.

В benchmark/results.local.json сохраняются запросы, эталоны, найденные ID, ответ и источники,
Recall@k и MRR@k. Ловушки исключены из метрик поиска.
Демо-провайдер для учебного прогона запрещён.

## Ручная оценка ответов

Прочитайте сохранённые ответы и создайте benchmark/review.json — объект с оценками для всех 15 ID:

```json
{"Q01":true,"Q02":false,"T01":true}
```

Пример сокращён. true для обычного вопроса означает полностью правильный ответ по эталону,
для ловушки — корректный отказ без выдуманных сведений. Оцените также правильность источников.
Затем:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/python.ps1 -m benchmark.run benchmark/dataset.json --review benchmark/review.json
```

Оценки применяются к уже сохранённым ответам в results.local.json, без повторного вызова LLM.
Появятся Accuracy (по 10 обычным вопросам) и Correct Rejection Rate (по 5 ловушкам).
До ручной оценки значения этих метрик равны null.
Не меняйте файл результатов между чтением ответов и внесением оценок.

## К сдаче

Добавьте короткий разбор ошибок: ID вопроса, ожидаемый результат, что вернула система,
где причина (корпус / BM25 / контекст / LLM), что исправили.
Сохраните версию корпуса, кода, параметров BM25, глубину k, модель и параметры LLM.
results.local.json исключён из Git; проверенный отчёт можно отдельно сохранить под осмысленным именем,
например results-bm25-v1.json.
